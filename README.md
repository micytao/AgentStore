# Agent Store (prototype)

Internal catalog of governed AI agents. Browse by department, launch a task, and either work interactively (Collaborative / C) or approve a draft (Autonomous / A).

This is a thin OpenShift-ready prototype. It is not the six-phase platform.

## Run locally

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). There is no per-user
login; every task is attributed to `Demo`. Click the **Demo** chip at the
bottom of the sidebar to switch to **Admin** — see **Admin console** below.

### C — Collaborative Mode (Engineering)

1. Catalog → Engineering → **Claude Code** → Launch.
2. Wait until status is Running, then type in the terminal.
3. Stop session. The task appears under **My Tasks**.

Without `OPENSHELL_GATEWAY_URL`, Collaborative Mode uses a simulated session (clearly labeled). With the gateway set and the `openshell` CLI on PATH, Engineering listings provision a real sandbox.

### A — Autonomous Mode (Support / Security / Data)

1. Catalog → Customer Support → **Draft a ticket reply**.
2. Goal example: `Draft a reply to INC-1042 about a billing outage`.
3. Wait for **AwaitingApproval**, read the draft, Approve or Reject.

By default the draft text is simulated (canned per-listing text). Add a real
model provider in **Admin → Providers** (see below) to have that draft
generated by an actual model call instead.

### Admin console

Click the **Demo** chip at the bottom of the sidebar to switch to **Admin**
— no passcode or login, one click. This is a demo convenience, not real
access control (see `docs/DEFERRED.md`): the role is still tracked in a
signed, `httpOnly` session cookie that every `/api/admin/**` route checks
server-side (`apps/web/src/server/auth.ts`), so it's a real server-side
fact rather than a client-only `localStorage` flag, but anyone can flip it.

Once switched to Admin, the console has six tabs backed by real, functional
integrations, not just config forms:

- **Catalog** — edit the six built-in demo listings, bind a per-agent
  provider/tools/skills/engine-override (**Agent config**), or click
  **+ Onboard new agent** to run the 5-step wizard that creates a brand-new
  agent (writing a real YAML file into a writable custom-listings
  directory) and publishes it into the regular catalog. See
  `docs/DEMO.md` step 7 for the full walkthrough.
- **Providers** — add a real API key for Anthropic, OpenAI, an OpenAI-compatible
  endpoint, or Gemini — or use the **Self-hosted / vLLM (MaaS)** quick preset,
  which needs no API key at all. "Test connection" makes a real call to the
  provider's models endpoint. Mark one provider active (or bind a specific
  one to a specific agent via Agent config); it's then used to generate real
  Autonomous-mode drafts (see `apps/web/src/server/drafting.ts`), with a
  fallback to the simulated text if no provider is configured or a call fails.
- **MCP** — register a real MCP server (stdio command, or a Streamable
  HTTP/SSE URL) and connect to it using `@modelcontextprotocol/sdk`. Enable
  individual tools globally, or scope a subset to one specific agent via
  Agent config. `stdio` servers spawn a local command you specify — only
  connect servers you trust.
- **Skills** — author reusable instruction bundles once, then attach one or
  more to any agent; a skill's instructions are merged into that agent's
  system prompt when it drafts.
- **Secrets** — an encrypted local vault (also used internally by Providers
  and MCP to store API keys and auth tokens) for the two engine-related
  tokens `OPENSHELL_GATEWAY_TOKEN` and `GIT_PAT`. A value saved here
  overrides the matching environment variable for the life of the server
  process. This is a local, prototype-grade vault — not a substitute for a
  real secrets manager (see `docs/DEFERRED.md`).
- **Engine** — force-simulate task execution store-wide, or per listing via
  the same Agent config engine override.

## Configuration

| Variable | Purpose |
| --- | --- |
| `OPENSHELL_GATEWAY_URL` | If set, Engineering `work-with-me` listings use the OpenShell adapter |
| `OPENSHELL_CREATE_ARGS` | Extra args inserted into `openshell sandbox create` |
| `CATALOG_DIR` | Override path to the built-in `catalog/listings` |
| `CUSTOM_CATALOG_DIR` | Override path to the writable custom-listings directory used by the Admin onboarding wizard (defaults to `.data/custom-listings`) |
| `SESSION_SECRET` | Key used to sign the Demo/Admin session cookie. Falls back to `SECRETS_ENCRYPTION_KEY`, then a hardcoded dev default — cosmetic in this prototype since there's no passcode gate, but keeps the cookie value itself from being hand-edited client-side |
| `SECRETS_ENCRYPTION_KEY` | Passphrase used to derive the local secrets-vault encryption key. If unset, a key is auto-generated and stored locally — set this explicitly for anything beyond local/demo use |
| `SECRETS_DATA_DIR` | Override path to the vault/provider/MCP/skills/tasks/catalog-overrides data directory (defaults to `.data`) |

Admin-configured providers, MCP servers, and secrets call out to real
external endpoints (model provider APIs, MCP server URLs) — outbound network
access from the server is required for those features to work, the same as
for `OPENSHELL_GATEWAY_URL`.

## Layout

- `apps/web` — Next.js storefront + BFF
  - `src/server/auth.ts` — server-tracked Demo/Admin session (signed cookie, no passcode)
  - `src/server/secrets.ts` — encrypted local vault (AES-256-GCM)
  - `src/server/providers.ts` — model provider registry + real chat/model-list calls
  - `src/server/mcp.ts` — real MCP client (`@modelcontextprotocol/sdk`), with per-agent tool scoping
  - `src/server/skills.ts` — file-backed skills library
  - `src/server/catalog.ts` — built-in + custom (wizard-created) listings, publish gate, file-backed overrides
  - `src/server/drafting.ts` — real Autonomous-mode draft generation (per-agent provider/tools/skills), with a simulated fallback
  - `src/server/orchestrator.ts` — task lifecycle, persisted to `.data/tasks.json`
- `packages/shared` — Listing / Task / AgentConfig / Skill types and `EngineAdapter`
- `packages/engine-fake` — Simulated engine (all business listings; Engineering when no gateway)
- `packages/engine-openshell` — CLI-backed Engine 1 adapter
- `catalog/listings` — built-in, git-tracked YAML catalog
- `.data/custom-listings` — agents created through the Admin onboarding wizard (gitignored; override with `CUSTOM_CATALOG_DIR`)
- `deploy/openshift` — Eval Helm values and app manifests
- `docs/DEMO.md` / `docs/DEFERRED.md`

See [docs/DEMO.md](docs/DEMO.md) for the leadership walkthrough.
